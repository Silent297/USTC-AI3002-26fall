### 4.1 QOS 拒绝与修正

首次提交使用 `--mem=32G` 且未声明 `--account`；课程 README 的 107 模板为 `--account=stu`、`--mem=16G`、4 小时。按模板改为 `--account=stu`、`--mem=16G`，其余不变。16G 对 56000×512 float32 数据、3000 点评价子集和候选模型足够。

若重新提交仍被拒绝，请在集群执行以下诊断并把输出回传：

```bash
squeue -u "$USER"
sacctmgr -n show qos qos_stu_default format=Name,MaxWall,MaxTRESPerUser,MaxJobsPU,MaxSubmitPU
sacctmgr -n show assoc user="$USER" format=Account,Partition,QOS,MaxWall,MaxJobs,MaxSubmit,GrpTRES
scontrol show partition Students | grep -E "MaxTime|TRES|QoS"
```

它们分别用于确认：是否有占满提交限额的排队作业、QOS 的墙钟与资源上限、账户关联的限制、分区本身的上限。若墙钟上限低于 4 小时，再按实际上限下调 `--time`。

### 4.2 作业 177587：Slurm spool 路径问题与修正

作业 177587 的 `.err` 显示：

```text
mkdir: cannot create directory '/var/spool/logs': Permission denied
mv: cannot move '.../lab2-q2-full_177587.out' to '/var/spool/logs/T0008/...': No such file or directory
tee: /var/spool/logs/T0008/.../job.log: No such file or directory
FAIL(2): self-check-float32
```

`.out` 显示 GPU 自检通过（`torch 2.11.0+cu128`、`NVIDIA A100-SXM4-80GB`），随后 `python: can't open file '/var/spool/slurmd/job177587/extras.py'`。

原因：Slurm 把批处理脚本复制到 `/var/spool/slurmd/job<id>/` 执行，`BASH_SOURCE[0]` 指向 spool 副本，脚本据此反推仓库根得到 `/var/spool`。修正为优先用 `SLURM_SUBMIT_DIR` 定位包含 `extras.py` 的 `code/q2_clustering`，并校验存在性；输出目录改为 `RUN_ID=时间戳_JobID`，避免重复。修正后本地三条冒烟路径均按预期退出。

**未验证**：修正版尚未在集群重新执行；GPU 环境本身已由作业 177587 证明可用。

未验证：集群 ai26 是否有 CUDA torch、A100 是否可用、实际排队与耗时、32 个候选在 56000 行上的完整结果。这些只能由实际作业确认。

## 5. 用户执行步骤（assistant 不代 ssh）

本地提交后：

```bash
git push
```

集群侧（用户执行）：

```bash
ssh ustc
cd ~/USTC-AI3002-26fall && git pull
cd LABs/LAB2/code/q2_clustering
sbatch run_q2_T0008.sbatch
squeue -u pb25030753
```

说明：

- 必须在 `code/q2_clustering` 目录提交，脚本用 `SLURM_SUBMIT_DIR` 定位 `extras.py`；从仓库根提交时脚本会尝试 `$SLURM_SUBMIT_DIR/LABs/LAB2/code/q2_clustering`，找不到则退出 1。
- 平台上若还有未提交的手工改动，先 `git status --short && git diff`；确认与本次修正不冲突后再 pull，不要直接覆盖。
- 若 GPU 自检返回 2 且提示无 CUDA torch，先在 ai26 中安装 `code/requirements-gpu.txt` 一次，再重新提交；不要改用 `gpu:1`。
- 作业日志与 `.out/.err`：`LABs/LAB2/logs/T0008/<stamp>_<jobid>/`。
- 成功时日志末尾打印 `ARTIFACT_DIR`、`FIT_DIR`、`EVAL_DIR`。
- 失败时保留日志与半成品目录，用新的时间戳重新提交，不覆盖旧目录。
