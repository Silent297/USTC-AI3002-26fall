# 超参数实验说明

本目录提供一套「只改一个超参数」的对照实验配置和执行器，用来在 LAB1 的两个任务上
（`truth` 真假分类、`world` 经纬度回归）系统地测试学习率、训练轮数、L1/L2 正则化系数
和隐表征层数的影响。

## 文件

| 文件 | 作用 |
| --- | --- |
| `hparam_grid.json` | 分组超参数配置（要测哪些值、哪些固定） |
| `run_grid.py` | 读取配置、逐组训练、把结果写成 JSON |

## 在本科生算力平台上怎么用

平台用 Slurm 管任务，所以流程是：**登录节点上写脚本、提交作业、看日志、取结果**。
不需要在登录节点直接跑训练（登录节点不适合长时间计算）。

### 1. 上传代码或拉取仓库

在集群上准备好仓库（例如 `~/repo/USTC-AI3002-26fall`），确保
`LABs/LAB1/experiments/` 下的两个文件都在。用 `scp` / `sftp` 上传，或者直接在
集群上 `git clone`。

### 2. 配置并激活 conda 环境

参考实验文档附录 A/B，集群上一般需要显式 source conda：

```bash
set +u
source ~/miniforge3/etc/profile.d/conda.sh
conda activate ai26
set -u
```

确认：`python -c "import numpy, pandas"` 不报错。

### 3. 写一个 Slurm 作业脚本

和文档附录 B.4.2 的模板一致，把 `cd` 改成仓库里 `experiments` 的父目录，然后调用
`run_grid.py`：

```bash
#!/bin/bash
#SBATCH --job-name=lab1-grid
#SBATCH --output=%x_%j.out
#SBATCH --error=%x_%j.err
#SBATCH --partition=Students
#SBATCH --qos=qos_stu_default
#SBATCH --cpus-per-task=4
#SBATCH --mem=16G
#SBATCH --time=4:00:00

set -euo pipefail

cd ~/repo/USTC-AI3002-26fall/LABs/LAB1

set +u
source ~/miniforge3/etc/profile.d/conda.sh
conda activate ai26
set -u

python experiments/run_grid.py --config experiments/hparam_grid.json
```

把上面保存成 `grid.sbatch`，在登录节点执行 `sbatch grid.sbatch` 提交。

> 注意：LAB1 这两个任务只用 numpy/pandas，**不需要 GPU**，所以模板里没写
> `#SBATCH --gres=gpu:1`。真要用 GPU 时再加。

### 4. 只看某几个组

`run_grid.py` 支持 `--groups`，用逗号分隔组名，只跑需要的组，省时间：

```bash
python experiments/run_grid.py --config experiments/hparam_grid.json --groups truth_lr,world_lr
```

### 5. 结果放在哪

结果默认写到配置文件同目录的 `results.json`，可以用 `--out` 指定其它路径：

```bash
python experiments/run_grid.py --config experiments/hparam_grid.json --out results/grid_run1.json
```

`results.json` 是列表，每条记录包含：`group`、`task`、`layer`、变化的键和值、
四个超参数、指标（`accuracy` 或 `mse`）、`finite`（是否数值稳定）、`seconds`。
把 `results/` 目录一起带回本地分析，或者直接在集群上看。

## 配置格式

`hparam_grid.json` 是「分组 + 控制变量」结构：

```json
{
  "base": { "lr": 0.001, "epochs": 10000, "lambda1": 0.01, "lambda2": 0.01 },
  "groups": [
    {
      "name": "truth_lr",
      "task": "truth",
      "layer": 11,
      "fixed": { "epochs": 500, "lambda1": 0.001, "lambda2": 0.001 },
      "vary": { "lr": [0.01, 0.005, 0.002, 0.001, 0.0005] }
    }
  ]
}
```

规则：

- `base` 是所有组的默认超参数。
- `fixed` 覆盖 `base`，把不研究的量钉死，**保证同一组内是单变量对比**。
- `vary` 里只有一个键，它的每个取值生成一次训练。
- 若 `vary` 的键是 `layer`，则 `layer` 字段填 `null`，层数由 `vary` 驱动。

要加一组实验，往 `groups` 里追加一个对象即可，不用改 `run_grid.py`。

## 内置的组

共 9 组，取值依据是在**未标准化**特征上探测得到的稳定范围：

| 组名 | task | 变化的量 | 取值 |
| --- | --- | --- | --- |
| `truth_lr` | truth | lr | 0.01 / 0.005 / 0.002 / 0.001 / 0.0005 |
| `truth_epochs` | truth | epochs | 200 / 500 / 1000 / 2000 |
| `truth_lambda1` | truth | λ1 | 0 / 0.001 / 0.01 / 0.1 |
| `truth_lambda2` | truth | λ2 | 0 / 0.001 / 0.01 / 0.1 |
| `truth_layer` | truth | layer | 11 / 23 / 35 |
| `world_lr` | world | lr | 0.0005 / 0.0002 / 0.0001 / 0.00005 |
| `world_epochs` | world | epochs | 500 / 1000 / 2000 / 4000 |
| `world_lambda2` | world | λ2 | 0 / 0.001 / 0.01 / 0.1 |
| `world_layer` | world | layer | 11 / 23 / 35 |

## 必须在 Bash 里注意的几点

1. **world 的 lr 不能超过 0.0005**。未标准化特征下 lr=0.001 会直接梯度溢出
   （`loss=inf`、`mse=inf`）。所以 `world_lr` 的上限卡在 0.0005。
2. **中文 print 在部分终端会乱码或让 `conda run` 报 UnicodeEncodeError**。作业脚本里
   建议加一行 `export PYTHONIOENCODING=utf-8`，或用 `conda activate` 之后再跑（不要用
   `conda run`，它在 Bash 管道下偶尔会因编码崩）。
3. **时间估算**：truth 单次 500 轮约 18-40 秒，一个 4~5 值的组约 2-3 分钟；
   world 单次 2000 轮约 12-25 秒。全部 9 组大约十几分钟量级，`--time=4:00:00` 足够。
4. **结果可复现**：脚本没有随机成分（梯度下降是确定性的），同一个配置重跑结果一致。
5. **这些范围是「未标准化」下测的**。若之后加入特征标准化，world 的可用 lr 量级会
   改变，需要重新调整 `hparam_grid.json` 后重跑。

## 本地快速自检

提交大作业前，可以先在本地跑一个小组确认环境没问题：

```bash
python LABs/LAB1/experiments/run_grid.py --config LABs/LAB1/experiments/hparam_grid.json --groups truth_lr
```

正常会打印每个取值的 accuracy 和耗时，并在同目录生成 `results.json`。
